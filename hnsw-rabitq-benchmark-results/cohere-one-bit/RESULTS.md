# Cohere-medium-1M 对比：Zvec HNSW-RaBitQ vs Elasticsearch 8.18.8 BBQ-HNSW

同一台机器、同一套脚本，与 `../gist-one-bit/RESULTS.md` 的 GIST-1M 实验口径一致。

## 1. 环境与数据

| 项 | 值 |
|---|---|
| CPU | Intel Xeon 6982P-C，8 物理核 / 16 逻辑核，单 socket 单 NUMA |
| 绑核 | `0,2,4,6,8,10,12,14`，Zvec 进程、ES client、ES JVM 同一 cpuset |
| 内存 | 61 GiB，swap 关闭 |
| Zvec commit | `c2a9db0`（Release，Python 3.11.15） |
| Elasticsearch | 8.18.8，rootless Docker，1 shard / 0 replica / `_source` 关闭，JVM 4 GiB |
| 数据集 | `/data/cohere_medium_1m`（`cohere-parquet`），1,000,000 / 1,000，768 维，**cosine**，GT 宽度 1000，SHA-256 `4565da2063dd…e601d8` |
| 索引参数 | `M=16`，`ef_construction=100`，build threads 8，搜索线程 `1,4,8` |
| 引擎配置 | Zvec `HNSW_RABITQ`（`num_clusters=16`，metric COSINE） vs ES `bbq_hnsw`（`cosine`） |
| 吞吐测量 | 每点 1000 query accuracy pass + 1000 预热 + 3 × 10 s 取中位数 |

与 GIST 的关键差异：Cohere 是 768 维归一化文本 embedding，1-bit 量化本身
友好得多，两个引擎的绝对 Recall 都远高于 GIST。

## 2. 构建

| 指标 | Zvec 1-bit | Zvec 7-bit | Elasticsearch bbq_hnsw |
|---|---:|---:|---:|
| ingest_seconds | 54.4 | 55.8 | 285.0 |
| finalize_seconds | 281.2 | 325.0 | 608.8 |
| **total_seconds** | **335.6** | **380.8** | **893.8** |
| 最终存储 | 3.16 GiB | 3.73 GiB | 4.77 GiB |

Zvec 1-bit 构建端到端比 ES 快 **2.66×**，存储小 **1.51×**；7-bit 快 **2.35×**，
存储小 **1.28×**。ES 存储包含磁盘保留的原始 FP32 向量（1-bit 查询不使用，但
`rescore_vector` 需要）。每引擎只构建 1 次，未取 3 次中位数。

## 5. 纯 1-bit 无精排口径（与 GIST 同口径）

| 线程 | Zvec 最优点 | ES 最优点 | 说明 |
|---:|---|---|---|
| 1 | 0.765 @ 309 QPS | 0.749 @ 203 QPS | Zvec Recall 高 0.016，QPS 高 1.5× |
| 4 | 0.765 @ 1344 | 0.749 @ 748 | 1.8× |
| 8 | 0.765 @ 2833 | 0.749 @ 1192 | 2.4× |

与 GIST 不同，Cohere 上 ES 纯 1-bit 的 Recall 区间（0.679–0.749）与 Zvec
（0.702–0.765）大幅重叠，两条曲线可直接比较：同 Recall 处 Zvec 领先 5.7×–15.4×
（见 §4 的 0.71/0.74 行）。

## 6. 扩展性

| 配置 | 1→8 线程加速比（参数=32） | 1→8 线程（参数=1000） |
|---|---:|---:|
| zvec-1bit | 5.47× | 9.15× |
| zvec-7bit | 7.12× | 8.83× |
| es-none | 1.91× | 5.87× |
| es-ov5 | 3.84×（参数=64） | 7.83× |

ES 在 8 线程处 QPS 饱和在约 1400–1455，与 `num_candidates` 基本无关（无精排时
1447→1192），瓶颈在 HTTP/协调层与单 shard 搜索线程池；开精排后 QPS 才与
`num_candidates` 强相关。

## 7. 结论

- Cohere-medium-1M（768 维 cosine）上，1-bit 量化对两个引擎都友好得多：
  ES 纯 BBQ 就能到 Recall@10 0.749（GIST 上只有 0.322）。
- 构建：Zvec 比 ES 快 2.35×–2.66×，存储小 1.28×–1.51×。
- 等 Recall 检索：Zvec 在 0.71–0.98 全区间领先，倍数随 Recall 升高而收窄
  （15.4× → 2.0×），随并发升高而扩大。
- 高 Recall 区（≥0.98）ES 用 `oversample=5` 精排可以做到 0.9924，超过 Zvec
  7-bit 的 0.9806 上限；这一档要靠原向量精排，代价是 QPS 明显更低。
- 相对 GIST 的结论变化：GIST 上 Zvec 优势为 3.9×–12.6×（且 ES 无精排完全不可用），
  Cohere 上收窄为 1.5×–15.4×，高 Recall 端差距明显更小。
- 口径限制同 GIST：两者量化/距离估计/HNSW 实现不同；ES QPS 含宿主机 HTTP 往返，
  Zvec 为进程内调用；每引擎仅构建 1 次；未采集峰值 RSS 与容器峰值内存；
  本机仅 8 物理核，无 16 线程点。
